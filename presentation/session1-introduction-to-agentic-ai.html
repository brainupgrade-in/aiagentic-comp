01

What is Agentic AI?

Definition · The Agent Loop · Core Capabilities

Let's Start Simple

How do you get things done with software today?

Traditional Software

You tell it exactly what to do

"Sort this list alphabetically"

AI Agent

You tell it what you want

"Organize my messy notes into a report"

What is an AI Agent?

An AI Agent is a software system that can
understand a goal, make a plan, take actions, and
adapt based on results
— all on its own.

You hire a new employee. You don't tell them every keystroke — you say "Research our competitors and write a summary." They figure out where to look, what to read, and how to write it up. An AI agent works the same way.

The Agent Loop

This is what makes agents different

🧠 Think
What should I do next?
⚡ Act
Use a tool / take action
🔄 Observe
Check the result
✅ Done?
Goal met or keep going?

This Think → Act → Observe loop repeats until the agent achieves its goal.

Real-World Example

"Book me a good Italian restaurant for Saturday"

System What It Does
Search Engine Shows you a list of links — you do the rest
Chatbot Suggests restaurant names — you call and book
LLM Writes a nice list with pros/cons — still you book
AI Agent Searches reviews, checks availability, compares ratings,
books a table, and sends you a confirmation
The agent doesn't just know things — it does things.

Three Core Capabilities of Agents

Autonomy

🧭

Decides what to do and how to do it without being told each step

Problem Solving

🧩

Breaks complex problems into smaller pieces and solves them one by one

Adaptability

🔄

When Plan A fails, it tries Plan B. Learns from each attempt.

These three capabilities together are what separate an agent from every other AI system. An LLM without these is just a very smart text generator.
02

How We Got Here

LLM vs Agent · The Evolution of AI · From Chatbots to Agents

LLM vs Agent

What's the difference?

LLM (Large Language Model)

The Brain

  • Understands language
  • Generates text
  • One question → one answer
  • No memory between chats
  • Cannot take actions

AI Agent

Brain + Body

  • Uses an LLM as its brain
  • Plans multiple steps
  • Remembers previous context
  • Calls tools and APIs
  • Loops until the goal is met
An LLM is like a brilliant person sitting in a locked room — they can answer any question you slide under the door, but they can't get up and do anything. An agent gives that person legs, hands, a phone, and a computer.

The Evolution of Software Intelligence

📋 Rule-Based if/else logic
→
📊 Machine Learning learns from data
→
💬 LLMs understands language
→
🤖 AI Agents thinks + acts
Each step added a new capability. Agents combine all of them: rules + learning + language understanding + autonomous action.

Evolution: A Closer Look

Era How It Works Example Limitation
Rule-Based Human writes every rule manually Spam filters: "if contains 'free money' → spam" Can't handle situations the programmer didn't anticipate
Machine Learning Learns patterns from historical data Netflix recommendations based on your watch history Narrow — only does one specific task
LLMs Understands and generates human language ChatGPT answering questions Just talks — can't take actions or use tools
Agents Reasons, plans, uses tools, adapts AI that researches, books, and plans your entire trip Still evolving — that's why you're here!

Chatbot vs RAG vs Agent

Chatbot RAG System AI Agent
What it does Answers questions from its training Looks up documents, then answers Reasons, plans, uses tools, takes actions
Memory Within one conversation Has access to a knowledge base Short-term + long-term memory
Can take actions? No No Yes — calls APIs, writes files, etc.
Multi-step? No — single turn Partially — retrieve + generate Yes — chains many steps
Adapts if stuck? No No Yes — tries alternative approaches
A chatbot is like a librarian who answers from memory. A RAG system is a librarian who looks things up in books first. An agent is a personal assistant who looks things up, makes calls, fills out forms, and follows up.

Architectural Patterns

Single Agent · Multi-Agent · Supervisor/Worker

Pattern 1: Single Agent

One agent does everything

👤 User
→
🤖 Agent
thinks + plans + acts
→
🔧 Tools

When to use

  • Simple, well-defined tasks
  • One domain of expertise needed
  • Quick prototyping

Limitations

  • Gets overwhelmed with complex tasks
  • Single point of failure
  • Can't specialize in multiple areas
Like a solo freelancer. Great for small projects, but can't build an entire skyscraper alone.

Pattern 2: Multi-Agent System

Multiple specialized agents collaborate

👤 User
→
🔍 Research Agent
✍️ Writer Agent
🔎 Reviewer Agent
→
📄 Result

Why this works

Each agent is an expert in its area. They pass work to each other, just like a team of specialists in a company.

Like a newsroom: one reporter researches, another writes the story, an editor reviews it. Each does what they're best at.

Pattern 3: Supervisor / Worker

One agent manages the others

👔 Supervisor Agent
assigns tasks, collects results
↙   ↓   ↘
🔧 Worker 1
Data lookup
🔧 Worker 2
Calculation
🔧 Worker 3
Report writing

Best of both worlds

Supervisor handles planning and coordination. Workers handle execution. No one agent needs to know everything.

Like a project manager who doesn't write code but knows who to assign each task to and how to combine their outputs into a final deliverable.

Choosing the Right Pattern

Pattern Best For Complexity Example
Single Agent Simple tasks, one skill area Low Q&A bot, calculator agent
Multi-Agent Tasks needing diverse expertise Medium Content creation pipeline
Supervisor/Worker Complex tasks with coordination High Customer support with specialists
Start simple. Use a single agent first. Add more agents only when you hit the limits of what one agent can handle. You'll build all three patterns in this course.

Agent Components

The Four Building Blocks of Every Agent

Four Building Blocks

🧠 LLM (Brain)

Core reasoning and
language understanding

💾 Memory (State)

Maintains context and
conversation history

🔧 Tools (Actions)

External capabilities like
APIs, databases, web

📋 Planning (Orchestration)

Task decomposition and
execution strategy

Think of a human worker: they have a brain to think, memory to remember context, hands to use tools, and a plan for how to approach the work. An agent is built the same way.

🧠 Component 1: LLM (The Brain)

What it does

  • Understands user requests in natural language
  • Reasons about what steps are needed
  • Decides which tool to use and when
  • Generates human-readable responses

Examples

GPT-4, Claude, Llama, Gemini, Groq-hosted models

In This Course

Day 1: Ollama + Llama 3.2 (local)
Day 2+: Groq API (cloud, free)

The LLM is the most critical component. A better brain = a better agent. But a brain alone can't do much — it needs the other three components.

💾 Component 2: Memory (The State)

Short-Term Memory

Current conversation context

"The user just asked about flights to Paris"

Long-Term Memory

Persistent knowledge across sessions

"This user prefers window seats"

Episodic Memory

Past experiences and outcomes

"Last time API X failed, API Y worked"

Without memory, every interaction starts from zero. Memory is what allows an agent to have context and get better over time.

🔧 Component 3: Tools (The Hands)

How agents interact with the real world

Search & Retrieve

  • Web search
  • Database queries
  • Document lookup

Compute & Analyze

  • Calculator
  • Code execution
  • Data analysis

Create & Write

  • Generate files
  • Send emails
  • Create reports

External APIs

  • Weather data
  • Booking systems
  • Payment gateways

Tools are what transform an LLM from a "text-in, text-out" system into something that can actually do work in the real world.

📋 Component 4: Planning (The Strategy)

How an agent approaches: "Plan my vacation to Japan"

Step 1: Research best time to visit Japan 🔍 search tool
↓
Step 2: Find flights within budget ✈️ flight API
↓
Step 3: Book hotels near attractions 🏨 booking API
↓
Step 4: Create day-by-day itinerary 📄 document tool

The agent breaks down a complex goal into an ordered sequence of actions, choosing the right tool for each step.

Question 1 of 5
What is the key difference between a traditional LLM and an AI Agent?
A An agent uses a bigger model with more parameters
B An agent can take actions, use tools, and work in a loop until a goal is met
C An agent always gives more accurate answers than an LLM

Answer: Question 1
What is the key difference between a traditional LLM and an AI Agent?
A An agent uses a bigger model with more parameters
B An agent can take actions, use tools, and work in a loop until a goal is met
C An agent always gives more accurate answers than an LLM
D An agent doesn't need an LLM at all — it works on pure logic
Why B? An LLM is just the "brain" — it generates text. An agent wraps the LLM with tools, memory, and a planning loop (Think → Act → Observe) so it can actually do work in the real world. The model size doesn't matter — it's the architecture around it.
Question 2 of 5
Which architectural pattern uses a manager agent that delegates tasks to specialized worker agents?
A Single Agent pattern
B Multi-Agent peer-to-peer pattern
C Supervisor / Worker pattern
D RAG pipeline pattern
Answer: Question 2
Which pattern uses a manager agent that delegates to worker agents?
A Single Agent pattern
B Multi-Agent peer-to-peer pattern
C Supervisor / Worker pattern
D RAG pipeline pattern
Why C? In the Supervisor/Worker pattern, one agent acts as a project manager — it understands the overall goal, breaks it into sub-tasks, and delegates each to a specialized worker. Multi-Agent (B) is close, but those agents are peers without a central coordinator.
Question 3 of 5
What are the four building blocks of every AI Agent?
A Input, Processing, Output, Storage
B LLM (Brain), Memory (State), Tools (Actions), Planning (Orchestration)
C Frontend, Backend, Database, API
D Data Collection, Training, Inference, Deployment
Answer: Question 3
What are the four building blocks of every AI Agent?
A Input, Processing, Output, Storage
B LLM (Brain), Memory (State), Tools (Actions), Planning (Orchestration)
C Frontend, Backend, Database, API
D Data Collection, Training, Inference, Deployment
Why B? The LLM thinks, Memory provides context, Tools let it take real-world actions, and Planning coordinates everything. Options A and C describe general software architecture, and D describes the ML lifecycle.
Question 4 of 5
A user asks: "What's the weather in Tokyo?"
A chatbot answers from training data. A RAG system looks up a knowledge base.

What would an AI Agent do differently?
A Give the same answer but faster
B Refuse to answer because it's not trained on weather data
C Call a live weather API to get the current, real-time temperature
D Search its own memory for the last known weather
Answer: Question 4
What would an AI Agent do differently for a weather query?
A Give the same answer but faster
B Refuse to answer because it's not trained on weather data
C Call a live weather API to get the current, real-time temperature
D Search its own memory for the last known weather
Why C? This is the power of tools. The agent recognizes that weather data changes constantly, decides it needs live information, selects the weather API tool, calls it, and returns the real-time result.

What does the agent do next?
A Crashes with an error and stops
B Returns "I don't know" to the user
C Waits forever until the website comes back
D Adapts — tries an alternative booking site or informs the user with options
Answer: Question 5
Agent tries to book a hotel but the website is down. What happens next?
A Crashes with an error and stops
B Returns "I don't know" to the user
C Waits forever until the website comes back
D Adapts — tries an alternative booking site or informs the user with options
Why D? Adaptability is one of the three core capabilities of agents (along with Autonomy and Problem Solving). When Plan A fails, the agent doesn't give up — it observes the failure, re-plans, and tries a different approach.
