01

LangFuse Overview

Open-Source LLM Observability

Why LangFuse?

Prometheus tells you “latency is high”. LangFuse tells you which prompt caused it.

What Prometheus + OTel Can’t Do

  • Show the exact prompt sent to the LLM
  • Display the LLM’s response text
  • Compare prompt versions side by side
  • Track cost per user or per conversation
  • Collect user feedback on responses
  • A/B test different prompt templates

What LangFuse Adds

  • Full LLM I/O: every prompt and completion
  • Prompt management: version, compare, rollback
  • Cost tracking: per model, per user, per session
  • User feedback: thumbs up/down, scores
  • Evaluation: automated quality scoring
  • Self-hosted: data stays in your cluster

LangFuse Trace Hierarchy

Three levels of nesting for complete visibility

TRACE chat_session_42 — user: alice — total: 2.1s
  SPAN agent_workflow [0ms → 2100ms]
    SPAN rag_retrieval [10ms → 55ms]
      GENERATION embedding_call [12ms → 42ms]
        model: text-embedding-3-small — tokens: 24 — $0.0001
    SPAN llm_reasoning [60ms → 1800ms]
      GENERATION chat_completion [65ms → 1750ms]
        model: groq/llama3-70b — in: 850 out: 420 — $0.0038
    SPAN tool_execution [1800ms → 2050ms]
      GENERATION tool_call_result [1810ms → 2040ms]

Trace

Top-level: one per user request. Carries metadata (user, session, tags).

Span

Logical grouping within a trace. E.g., “rag_retrieval”, “tool_execution”.

Generation

Actual LLM call. Captures model, input, output, tokens, cost, latency.

LangFuse vs OpenTelemetry

Feature OpenTelemetry LangFuse
Scope General-purpose distributed tracing AI/LLM-specific observability
Prompt I/O Not captured (attributes only) Full prompt input + completion output
Token tracking Manual span attributes Automatic per-generation
Cost Manual calculation Built-in pricing per model
Prompt management Not supported Version, compare, rollback
User feedback Not supported Scores, ratings, annotations
Use together? Yes! OTel for infrastructure + LangFuse for AI logic
OTel and LangFuse are complementary. Use OTel for HTTP/DB/infrastructure tracing and LangFuse for AI-specific tracing (prompts, tokens, cost, feedback).

Instrumenting LangChain with LangFuse

Callback Handler · Trace Hierarchy · Feedback

Installation & Setup

# Install LangFuse SDK pip install langfuse # Environment variables LANGFUSE_PUBLIC_KEY="pk-lf-..." # From LangFuse project settings LANGFUSE_SECRET_KEY="sk-lf-..." # From LangFuse project settings LANGFUSE_HOST="http://langfuse:3000" # Self-hosted URL
# Initialize LangFuse client from langfuse import Langfuse langfuse = Langfuse( public_key="pk-lf-...", secret_key="sk-lf-...", host="http://langfuse:3000", ) # Verify connection langfuse.auth_check() # Returns True if connected

LangChain Callback Handler

One line to trace entire LangChain workflows

from langfuse.callback import CallbackHandler # Create handler for this request handler = CallbackHandler( public_key="pk-lf-...", secret_key="sk-lf-...", host="http://langfuse:3000", # Metadata for this trace user_id="alice", session_id="chat_42", tags=["production", "v2.0"], ) # Use with any LangChain component result = chain.invoke( {"question": "What is RAG?"}, config={"callbacks": [handler]} ) # LangFuse automatically captures: # - Every LLM call (input, output, model, tokens) # - Every tool call (name, arguments, result) # - Chain execution flow (parent → child spans) # - Retriever calls (query, documents returned)

Tracing a RAG Pipeline

from langchain_community.vectorstores import Chroma from langchain_groq import ChatGroq from langchain.chains import RetrievalQA from langfuse.callback import CallbackHandler # Setup RAG chain vectorstore = Chroma(persist_directory="./chroma_db") retriever = vectorstore.as_retriever(search_kwargs={"k": 5}) llm = ChatGroq(model="llama3-70b-8192") chain = RetrievalQA.from_chain_type( llm=llm, retriever=retriever, return_source_documents=True, ) # Create LangFuse handler handler = CallbackHandler( user_id="alice", session_id="session_123", metadata={"pipeline": "rag_v2"}, ) # Invoke with tracing result = chain.invoke( {"query": "How do Kubernetes probes work?"}, config={"callbacks": [handler]} )

Every LLM call is a Generation with full input/output text, token counts, cost, and model info. You can search, filter, and analyze these in the LangFuse UI.

User Feedback Collection

from langfuse import Langfuse langfuse = Langfuse() # After the user rates the response (e.g., thumbs up) langfuse.score( trace_id=handler.get_trace_id(), name="user_feedback", value=1, # 1 = positive, 0 = negative comment="Accurate and helpful response", ) # Or a numeric score (1-5 stars) langfuse.score( trace_id=handler.get_trace_id(), name="quality", value=4.5, comment="Good answer but slightly verbose", ) # Automated quality scoring langfuse.score( trace_id=handler.get_trace_id(), name="relevance", value=calculate_relevance_score(query, response), comment="Auto-evaluated by relevance model", )

Manual Scores

User thumbs up/down, star ratings, free-text feedback collected in the UI or via API.

Automated Scores

Programmatic evaluation: relevance, factuality, toxicity. Run on every trace automatically.

Prompt Management

Version, compare, and rollback prompts without code changes

# Fetch a managed prompt from LangFuse from langfuse import Langfuse langfuse = Langfuse() # Get the latest production prompt prompt = langfuse.get_prompt("rag_system_prompt") # Use in LangChain from langchain_core.prompts import ChatPromptTemplate template = ChatPromptTemplate.from_messages([ ("system", prompt.prompt), # Fetched from LangFuse ("human", "{question}"), ]) # The prompt is automatically linked to traces # You can see which prompt version produced which responses

Version Control

Each prompt edit creates a new version. Roll back to any previous version instantly.

A/B Testing

Label versions as “production” or “staging”. Route % of traffic to test new prompts before rollout.

Debugging AI Agents

Reasoning Steps · Tool Calls · Cost Analysis

Tracing Agent Reasoning

See every step the agent takes to answer a question

TRACE "What is the weather in Paris and how should I dress?"
  SPAN AgentExecutor [0ms → 4200ms]
    GENERATION Step 1: Plan [10ms → 800ms]
      output: "I need to check the weather first, then give clothing advice"
      tokens: in=120 out=45 — $0.0005
    SPAN Tool: weather_api [810ms → 1200ms]
      input: {"city": "Paris"} — output: {"temp": 12, "condition": "cloudy"}
    GENERATION Step 2: Synthesize [1210ms → 4100ms]
      output: "The weather in Paris is 12°C and cloudy. I recommend..."
      tokens: in=280 out=150 — $0.0012
Total: 2 LLM calls, 1 tool call — $0.0017 — 4.2s

Common Agent Debugging Scenarios

Agent in Infinite Loop

Symptom: High token cost, no final answer
In LangFuse: See 15+ generations in one trace. Agent keeps calling the same tool with slightly different params.
Fix: Add max_iterations limit, improve tool descriptions.

Wrong Tool Selected

Symptom: Incorrect or irrelevant response
In LangFuse: Step 1 shows agent chose “calculator” instead of “weather_api”.
Fix: Improve tool descriptions, add examples to system prompt.

High Latency

Symptom: Response takes 15+ seconds
In LangFuse: One generation shows 12s — the LLM call with a 5000-token context.
Fix: Reduce retrieved context, use smaller model for planning steps.

Hallucination

Symptom: Agent makes up facts
In LangFuse: Retriever returned 0 relevant docs but agent still answered confidently.
Fix: Add “say I don’t know” instruction, check retriever quality scores.

Question 1 of 5

What is the key advantage of LangFuse over OpenTelemetry for AI applications?

A LangFuse replaces OTel completely for all tracing needs
B LangFuse captures full prompt input/output, token costs, and supports prompt management
C LangFuse is faster and more efficient than OTel
D LangFuse supports more programming languages
B — AI-specific features. LangFuse captures what OTel can’t: the actual prompt text sent to LLMs, the full completion, automatic cost calculation, prompt version management, and user feedback scoring.
Question 2 of 5

In LangFuse’s trace hierarchy, what represents an actual LLM API call?

A Trace — the top-level container
B Span — a logical grouping of operations
C Generation — captures model, tokens, input/output
D Score — a quality measurement
C — Generation. In LangFuse’s hierarchy: Trace (per request) → Span (logical grouping) → Generation (actual LLM call with model, input, output, tokens, cost). Generations are the leaf nodes that represent real API calls.
Question 3 of 5

How do you integrate LangFuse with a LangChain application?

A Replace all LangChain imports with LangFuse equivalents
B Pass a CallbackHandler in the config parameter of chain.invoke()
C Wrap every LLM call with a langfuse.trace() decorator
D LangFuse reads LangChain logs from disk automatically
B — CallbackHandler. LangChain’s callback system makes integration minimal: create a CallbackHandler and pass it via config={"callbacks": [handler]}. LangFuse automatically captures all chain, retriever, and LLM operations.
Question 4 of 5

An agent trace shows 15 generations in a single request with $0.45 cost. What likely happened?

A The LLM model is very expensive per token
B The user asked a very complex multi-part question
C The agent entered an infinite loop, repeatedly calling tools without reaching a final answer
D LangFuse has a tracing bug causing duplicate generations
C — Infinite loop. 15 generations in one trace is a classic sign of an agent stuck in a loop. The fix: set max_iterations, improve tool descriptions so the agent picks the right tool, or add a “stop condition” in the system prompt.
Question 5 of 5

What is the benefit of managing prompts through LangFuse instead of hardcoding them?

A Prompts run faster when stored in LangFuse
B LangFuse automatically optimizes prompt wording
C You can version, compare, A/B test, and rollback prompts without deploying code
D LangFuse prompts are required for the callback handler to work
C — Version control without code deploys. LangFuse prompt management lets you iterate on prompts independently of code releases. You can A/B test prompt versions, see which produces better user feedback scores, and rollback instantly if quality drops.
