01

Reasoning Architectures

ReAct · Chain-of-Thought · Tree-of-Thought · Reflection

Key teaching points: Cover the four main reasoning architectures. ReAct interleaves thinking and acting. Chain-of-Thought breaks problems into sequential steps. Tree-of-Thought explores multiple reasoning paths in parallel. Reflection allows the agent to critique and improve its own output. Each pattern has different trade-offs for accuracy vs. cost vs. latency. Ask the audience: "When you solve a complex problem, do you think step-by-step (CoT) or explore multiple approaches (ToT)?"

Why Does Reasoning Matter?


Without Reasoning

"What's 17 x 28?"

LLM guesses: "436"

(Confident but wrong. Actual: 476)

With Reasoning

"What's 17 x 28?"

17 x 28
= 17 x 30 - 17 x 2
= 510 - 34
= 476


Reasoning forces the model to show its work rather than jumping to an answer. This dramatically improves accuracy on complex tasks.

Chain-of-Thought (CoT)

Think step by step before answering


Without CoT

Q: "A store has 15 apples. They sell 8 and receive a shipment of 20. How many now?"

A: "35" (might guess wrong)

With CoT

Q: Same question + "Let's think step by step."

A:
1. Start with 15 apples
2. Sell 8: 15 - 8 = 7
3. Receive 20: 7 + 20 = 27


Like showing your work on a math exam. Even if the final answer is easy, writing out each step prevents silly mistakes and helps you catch errors.

ReAct Pattern

Reasoning + Acting — The core agent pattern


Chain-of-Thought makes LLMs think better. But thinking alone isn't enough —
agents also need to act and observe results. ReAct combines both.


🧠 Reason
"I need to find X"
→
⚡ Act
Use search tool
→
👀 Observe
Read the result
↻ Repeat until goal is achieved

ReAct in Action

"What's the population of the capital of France?"

Thought 1
I need to find the capital of France first, then look up its population.
Action 1
search("capital of France")
Observe 1
Result: "Paris is the capital of France"
Thought 2
Now I know it's Paris. I need its population.
Action 2
search("population of Paris 2024")
Observe 2
Result: "Paris has approximately 2.1 million residents"
Thought 3
I have the answer. The capital of France is Paris with ~2.1M people.

Tree-of-Thought (ToT)

Explore multiple paths, pick the best one

📋 Problem
↙    ↓    ↘
Path A
Score: 6/10
Path B
Score: 9/10 ✓
Path C
Score: 3/10

How is this different from CoT?

Chain-of-Thought follows one path. Tree-of-Thought explores multiple paths, evaluates each, and picks the best. More expensive but better for complex decisions.

Like a chess player who considers 3 possible moves, thinks a few steps ahead for each, and then picks the move that leads to the best position.

Reflection Pattern

The agent reviews and improves its own work

Step 1: Agent produces an initial output
↓
Step 2: Agent critiques its own output — "Is this accurate? Did I miss anything?"
↓
Step 3: Agent produces an improved version
↻ Repeat if needed
Like writing a first draft, then re-reading it with fresh eyes and fixing mistakes. Professional writers always edit their own work — reflection lets agents do the same.

Reasoning Patterns: Summary

Pattern How It Works Best For Cost
Chain-of-Thought Think step by step in a single chain Math, logic, multi-step questions Low
ReAct Think, Act, Observe in a loop Tasks requiring external data or tools Medium
Tree-of-Thought Explore multiple paths, pick the best Complex decisions with multiple options High
Reflection Generate, critique, improve Content creation, code generation Medium

ReAct is the most commonly used pattern for agents because it naturally combines thinking with real-world actions. You'll implement it in today's hands-on lab.

Tool Calling

Why Tools Matter · API Patterns · Custom Tools

Key teaching points: Tools are what transform an LLM from a text generator into an agent that can act on the world. Cover the tool calling pattern: the LLM decides which tool to call, generates the arguments, and interprets the result. Each tool needs a name, description (so the LLM knows when to use it), and parameter schema. Ask the audience: "What external APIs or systems would be most valuable for an agent to access in your work?"

Why Tools Matter

LLMs are smart but limited


What LLMs Can't Do Alone

  • Access real-time data (weather, stock prices)
  • Do precise math reliably
  • Read your database
  • Send emails or make API calls
  • Execute code

What Tools Enable

  • Live web search and data retrieval
  • Precise calculations (calculator tool)
  • Database queries (SQL tool)
  • Sending messages and notifications
  • Running Python code safely

A brilliant person locked in a room can answer many questions from memory. Give them a phone, a computer, and internet access — now they can answer anything and get things done.

How Tool Calling Works


1. User
"What's the weather in Mumbai right now?"
2. LLM Thinks
I need live weather data. I should use the weather_api tool with location="Mumbai"
3. Tool Runs
weather_api(location="Mumbai") → {"temp": 32, "condition": "Partly Cloudy"}
4. LLM Reads
The API returned 32°C, Partly Cloudy for Mumbai.
5. Response
"It's currently 32°C and partly cloudy in Mumbai."

The LLM decides which tool to call and what parameters to pass. It doesn't execute the tool itself — the framework (LangChain) handles execution and sends the result back.

Common Tool Calling Patterns


Single Tool Call

Agent calls one tool to get an answer

"What time is it?" → clock_tool()

Sequential Calls

Output of one tool feeds into the next

search("CEO of Tesla") → lookup_bio(name="Elon Musk")

Parallel Calls

Multiple independent tools at once

weather("NYC") + weather("London") simultaneously

Conditional Calls

Choose which tool based on the situation

If math question → calculator, if factual → search

What Does a Tool Look Like in Code?


from langchain.tools import tool

@tool
def calculate(expression: str) -> str:
    """Calculate a math expression. Use this for any math question."""
    try:
        result = eval(expression)
        return str(result)
    except:
        return "Error: Invalid expression"

# The agent reads the docstring to know WHEN to use this tool
# LangChain handles calling it and returning the result

Three things every tool needs

  • A name — so the agent can refer to it
  • A description — so the agent knows when to use it
  • Parameters — so the agent knows what to pass in

Built-in vs Custom Tools


Built-in Tools (LangChain provides)

  • Web search (DuckDuckGo, Google)
  • Wikipedia lookup
  • Python code executor
  • File reader / writer
  • API request maker

Ready to use out of the box

Custom Tools (You build)

  • Your company's internal API
  • Database query tool
  • Email sender
  • Ticket booking system
  • Anything you can write in Python!

Just a Python function + @tool decorator


The beauty of tool calling: any Python function can become an agent tool. This means your agent can interact with any system your company uses. You'll build custom tools in today's lab.

Memory Systems

Short-Term · Long-Term · Episodic

Key teaching points: Memory is what gives agents continuity across interactions. Short-term memory is the conversation context (limited by the context window). Long-term memory persists across sessions (vector stores, databases). Episodic memory stores specific past experiences the agent can recall. Memory is the bridge between reasoning and tool use. Ask the audience: "What happens when an agent forgets everything between sessions? How would that affect a customer support bot?"

Why Memory Matters


Without Memory

You: "My name is Priya."
Agent: "Nice to meet you, Priya!"

You: "What's my name?"
Agent: "I don't know your name." 😐

With Memory

You: "My name is Priya."
Agent: "Nice to meet you, Priya!"

You: "What's my name?"
Agent: "Your name is Priya!" 😊


Memory = context. Without it, every message is a brand new conversation.

Three Types of Memory


Short-Term Memory

💬

Current conversation

Remembers what was said in this chat session

Like your working memory during a meeting

Long-Term Memory

🗄️

Across sessions

Persists information between separate conversations

Like notes you save in a file for later

Episodic Memory

📔

Past experiences

Remembers what worked and what failed before

Like learning from past mistakes

Short-Term Memory: Conversation Context


How does an agent "remember" what you just said?


Turn 1
User: "I'm planning a trip to Japan in March."
Agent: "Great choice! March is cherry blossom season."
Turn 2
User: "What should I pack?"
Agent: "For Japan in March, pack layers — it's 8-15°C..."
Turn 3
User: "And hotel recommendations?"
Agent: "For cherry blossom season in Japan, consider Kyoto..."

What's happening behind the scenes?

The agent includes the full conversation history with every request to the LLM. That's how it knows "there" means Japan and "then" means March. Simple but effective.

Long-Term Memory: Persistent Knowledge


Session 1 (Monday)

User: "I'm allergic to peanuts."
Agent: Saves to long-term memory

Session 2 (Friday)

User: "Suggest a Thai restaurant."
Agent: "Here are options that don't use peanuts, since you mentioned your allergy."


How it works

Information is stored in a vector database (like ChromaDB). Before answering, the agent searches this database for relevant past context. This is closely related to RAG — which we'll cover in depth on Day 2.

Episodic Memory: Learning from Experience

Attempt 1

Agent tries API-A to get flight prices
→ Failed (API-A is down)

Attempt 2

Agent remembers API-A failed, tries API-B instead
→ Success!

Next time a similar task comes up...

The agent recalls: "Last time API-A was unreliable. I'll try API-B first." This is episodic memory — the agent builds a library of what worked and what didn't for different situations.

Like a delivery driver who remembers that Main Street is always jammed at 5 PM, so they automatically take the alternate route without being told.

Memory: Putting It Together


Type Scope Duration Implementation
Short-Term Current conversation One session Conversation buffer / LangGraph state
Long-Term Across all sessions Permanent Vector database (ChromaDB)
Episodic Past task outcomes Permanent Experience logs / knowledge base

Most agents today use short-term memory well. Long-term and episodic memory are active areas of development — getting these right is what separates a demo agent from a production agent. You'll implement all three during this course.

Bringing It All Together

A complete agent interaction


"Find the cheapest flight from Delhi to Tokyo next Friday
and email me the details."

The Complete Flow

Think
I need to: 1) Find flights, 2) Compare prices, 3) Send email. Let me start with flights. (Planning)
Act
flight_search(from="DEL", to="TYO", date="next Friday") (Tool calling)
Observe
Found 5 flights. Cheapest is Air India at ₹38,500. (Reading result)
Think
I have the cheapest option. Now I need to email the user. I remember their email from our last conversation. (Memory)
Act
send_email(to="user@email.com", subject="Delhi-Tokyo Flight", body="...") (Tool calling)
Observe
Email sent successfully. (Confirming)
Done
"I found the cheapest flight — Air India at ₹38,500 on Friday. I've emailed you the full details!" (ReAct complete)

Every Concept in One Interaction


Chain-of-Thought

Agent broke the problem into 3 sub-tasks before starting

ReAct Loop

Think → Act → Observe repeated twice (search + email)

Tool Calling

Used flight_search and send_email tools with correct parameters

Memory

Remembered the user's email from a previous conversation


This is what you'll be building. Not just one piece — the complete system where reasoning, tools, and memory work together.

Question 2 of 5
What is the key difference between Chain-of-Thought and Tree-of-Thought?
A CoT uses tools, ToT does not
B CoT follows one path; ToT explores multiple paths and picks the best
C ToT is faster because it skips reasoning steps
D They are the same thing with different names
Correct answer: B — CoT follows one path; ToT explores multiple paths and picks the best. Chain-of-Thought is linear: step 1, step 2, step 3. Tree-of-Thought branches out, exploring several reasoning paths simultaneously, then evaluates and selects the best one. ToT is more expensive but better for complex problems with multiple valid approaches.
Answer: Question 2

B CoT follows one path; ToT explores multiple paths and picks the best
C ToT is faster because it skips reasoning steps
D They are the same thing with different names
Why B? CoT is a single linear path of reasoning. ToT branches out like a chess player considering multiple moves, evaluates each, and picks the best. More expensive but better for complex decisions.
Question 3 of 5
Every tool an agent uses needs three things. Which of these is NOT one of them?
A A name — so the agent can refer to it
B A description — so the agent knows when to use it

Correct answer: C — A training dataset — so the tool can learn. This is a trick question. Tools do NOT need training datasets — they are deterministic functions or APIs. Answer: Question 3

A A name — so the agent can refer to it
B A description — so the agent knows when to use it
C A training dataset — so the tool can learn
D Parameters — so the agent knows what input to pass
Why C? Tools are just regular Python functions — they don't learn or train. A tool needs a name, a description (the agent reads this to decide when to use it), and parameters (what inputs to provide).

Correct answer: B — Long-term memory. Long-term memory persists knowledge across sessions using external storage like vector databases. Short-term memory is just the current conversation context. Episodic memory stores specific past experiences. Cache memory is not a standard agent memory type.

Question 5 of 5

A Immediately returns it to the user

Correct answer: C — Critiques its own output and produces an improved version. Reflection is a self-improvement pattern where the agent evaluates its own output, identifies weaknesses, and generates an improved version. It does not require an external reviewer — the same LLM critiques itself using a different prompt.
