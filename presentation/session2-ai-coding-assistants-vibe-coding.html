How AI Coding Agents Work

Plan-Code-Test Loop · Tool Architecture · Context Management

The Agent Loop

Every AI coding agent follows this cycle

User Prompt
→
Plan
→
Code
→
Test
→
Reflect
← Loop back if tests fail or reflection finds issues →

Plan

Analyze the request, gather context, decide which files to read/modify

Code

Generate diffs, write new files, modify existing code

Test

Run tests, linters, build commands to validate changes

Reflect

Analyze test results, decide if done or needs another iteration

What Makes a Coding Agent?

Traditional Autocomplete

  • Single-line suggestions
  • No context beyond current file
  • No tool use (can't run commands)
  • Reactive — only completes what you type
  • No planning or reasoning

AI Coding Agent

  • Multi-file changes in one action
  • Codebase-wide context awareness
  • Runs tools: shell, tests, search, git
  • Proactive planning and task decomposition
  • Self-corrects based on feedback
Autocomplete is like a helpful spell-checker that finishes your sentence. A coding agent is like a junior developer who reads the whole codebase, writes code, runs the tests, and fixes bugs — all from a single instruction.

Core Architecture

Component Role Example
Context Engine Gathers relevant code from the codebase File search, grep, AST parsing, dependency graph
Planner Decides what to do and in what order "I need to modify 3 files to add this feature"
Code Generator Writes code as diffs or full files LLM generates edits based on plan + context
Tool Executor Runs commands in the environment bash, pytest, linters, git, file read/write
Validator Checks results and decides next step Parse test output, verify no errors, check types
These five components form a feedback loop. The agent keeps cycling through them until the task is complete or it decides to ask the human for help.

Tool Architecture

Pseudo-Python
TOOLS = { "read_file": read_file_contents, "write_file": write_file_contents, "search_code": grep_codebase, "run_tests": execute_pytest, "run_command": safe_bash_exec, } def agent_loop(task): plan = llm.plan(task, context) for step in plan.steps: tool = select_tool(step) result = TOOLS[tool.name](**tool.args) if not validate(result): plan = llm.replan(task, result) # adapt on failure

Read Tools

File contents, grep results, directory listings, git history

Write Tools

Create files, edit files, apply diffs, delete files

Execute Tools

Run shell commands, tests, linters, build scripts

Context Management

The KEY challenge for AI coding agents

Context Window Limits

  • LLMs have 8K-200K token windows
  • A typical codebase is millions of tokens
  • Can't send everything to the model
  • Wrong context = wrong code
  • Too much context = slow + expensive

Strategies

  • File relevance scoring (most related first)
  • AST-based extraction (functions, not full files)
  • CLAUDE.md / README.md priority loading
  • Recent edit history weighting
  • Dependency graph traversal
You're studying for an exam with 50 textbooks, but you can only bring 3 pages of notes into the exam room. Context management is the art of choosing which 3 pages contain the most useful information.

Token Budgeting

How agents allocate their limited context window

Priority Content Budget %
1 System prompt + instructions (CLAUDE.md, rules) 10-15%
2 User's current request 5-10%
3 Currently open / most relevant files 20-30%
4 Search results / grep output 20-30%
5 Tool outputs / test results 15-20%
6 Conversation history 10-15%
Higher priority content is never dropped. Lower priority items are summarized or truncated when the window fills up. This is why being specific in your prompts matters — it helps the agent find the right context faster.

Context Pipeline

How an agent gathers context before writing code

Step 1: Read CLAUDE.md / project instructions project rules
↓
Step 2: Search codebase for relevant files grep / glob
↓
Step 3: Read most relevant files fully file read
↓
Step 4: Assemble context + generate plan + code LLM call

The agent makes multiple tool calls before writing any code. Better context gathering = better code generation.

Plan-Code-Test in Action

Example: "Add input validation to the login endpoint"

# Agent's internal reasoning trace: 1. PLAN: - Search for login endpoint: grep "def login" across codebase - Found: auth/routes.py:42 - Read auth/routes.py and auth/models.py - Need to: add Pydantic validation, update tests 2. CODE: - Edit auth/models.py: add LoginRequest(BaseModel) with field constraints - Edit auth/routes.py: add request validation, proper error responses - Edit tests/test_auth.py: add validation test cases 3. TEST: - Run: pytest tests/test_auth.py - Result: 1 failure — test_login_empty_email expected 422 got 400 4. REFLECT: - Fix: update status code from 400 to 422 in route - Re-run: pytest tests/test_auth.py — ALL PASSED

Safety & Sandboxing

Agents run real commands — guardrails are essential

Allowed by Default

  • Read any file in the project
  • Search code with grep/glob
  • Run tests (pytest, npm test)
  • Git operations (status, diff, log)

Requires Approval

  • Write/edit files
  • Run arbitrary shell commands
  • Install packages
  • Network requests / API calls
AI coding agents can execute any command on your machine. Always review commands before approving, especially rm, git push --force, or commands touching production systems.

AI Coding Agent Landscape

Tools · Paradigms · Strengths · Trade-offs

The Current Landscape

Agent Paradigm Strengths Limitations
GitHub Copilot IDE plugin, inline Fast autocomplete, wide adoption, multi-IDE Limited multi-file, no autonomous execution
Cursor IDE-native, chat+edit Deep IDE integration, smart apply, composer mode Tied to Cursor editor, proprietary
Claude Code CLI terminal agent Full codebase context, autonomous, tool use, CLAUDE.md Terminal-only, requires API key
OpenCode CLI terminal agent Open source, multiple LLM backends, TUI interface Newer, smaller community
Windsurf IDE, cascade agent Flow-based multi-step, good at refactoring Proprietary, limited customization

CLI Agents vs IDE Agents

CLI Agents (Claude Code, OpenCode)

  • Full shell access — can run any command
  • Git-native workflow (commit, branch, diff)
  • Headless / scriptable (CI/CD integration)
  • Context from file system traversal
  • Works with any editor
  • CLAUDE.md for persistent project context

IDE Agents (Copilot, Cursor)

  • Visual diff previews before applying
  • Inline suggestions as you type
  • UI-integrated (hover, sidebar, panels)
  • Context from open tabs and cursor position
  • Lower barrier to entry
  • Settings-based configuration
CLI agents are like a skilled developer working in a terminal — they can do anything a human can do via command line. IDE agents are like a pair programmer sitting next to you, pointing at your screen and making suggestions.

How CLAUDE.md Works

Persistent project-level context for AI agents

# CLAUDE.md — placed in project root ## Project Overview This is a FastAPI microservice for order processing. Uses PostgreSQL, Redis for caching, deployed on K8s. ## Architecture Decisions - All endpoints are async - Pydantic v2 for validation - Alembic for DB migrations ## Commands - Run tests: pytest tests/ -v - Start dev: uvicorn main:app --reload - Migrate DB: alembic upgrade head ## Conventions - snake_case for functions, PascalCase for classes - Every endpoint must have a docstring - Never commit .env files
CLAUDE.md is loaded automatically at the start of every conversation. It gives the agent persistent context about your project without you repeating it every time. Think of it as onboarding docs for your AI teammate.

Choosing the Right Tool

Use Case Best Fit Why
Quick autocomplete while typing Copilot Fastest inline suggestions, zero context switch
Multi-file refactoring with preview Cursor / Windsurf Visual diffs, composer mode for large changes
Autonomous feature implementation Claude Code Full tool use, runs tests, self-corrects
Open-source / custom LLM backend OpenCode Bring your own model, fully customizable
Learning a new codebase Any CLI agent Can search, read, and explain the entire codebase

Vibe Coding & Prompt Engineering

Natural Language to Code · When to Use · Prompt Craft

What is Vibe Coding?

"You describe what you want in natural language, the AI writes the code, you review and guide."

— Andrej Karpathy (paraphrased)

When Vibe Coding Works

  • Prototyping and MVPs
  • Boilerplate and scaffolding
  • Standard patterns (CRUD, REST, forms)
  • Learning a new framework
  • Writing tests for existing code
  • Documentation and comments

When It Doesn't

  • Performance-critical hot paths
  • Security-sensitive code (auth, crypto)
  • Complex algorithms (custom data structures)
  • Highly custom business logic
  • Code that must meet regulatory compliance
  • Debugging subtle concurrency issues

Prompt Engineering for Code

Bad Prompt

"Fix the bug"

  • No file or location
  • No expected behavior
  • No error information
  • No validation criteria

Good Prompt

"Fix the TypeError in auth.py:42 — login() receives None for user_id when the session cookie is expired. Expected: redirect to /login"

  • Specific file and line
  • Error type and cause
  • Expected behavior

Great Prompt

Same as good + "Run the test suite after fixing and ensure test_login_expired passes"

  • Everything from "good"
  • Includes validation step
  • Agent can self-verify
The more context you give, the fewer iterations the agent needs. A great prompt saves 3-4 round trips of back-and-forth.

Structured Prompt Template

## Task [What you want to accomplish] ## Context [Relevant files, current behavior, constraints] - File: src/auth/routes.py - Current behavior: returns 500 on expired session - Constraint: must be backwards-compatible with v2 API ## Expected Behavior [What success looks like] - Return 401 with {error: "session_expired"} JSON body - Set WWW-Authenticate header ## Validation [How to verify the fix: tests, commands, manual checks] - Run: pytest tests/test_auth.py -k test_expired_session - Run: curl -H "Cookie: session=expired" localhost:8000/api/me - Expected: HTTP 401 with JSON error body
This template is like a well-written Jira ticket. The developer (or agent) reading it knows exactly what to do, where to look, and how to verify the result — without asking 5 clarifying questions.

NL-to-Application Flow

From description to working code

Natural Language: "Build a REST API for a todo app with CRUD"
↓
Parse Intent: REST API, CRUD operations, todo resource
↓
Generate Structure: models.py, routes.py, tests/, requirements.txt
↓
Generate Code: FastAPI endpoints, Pydantic models, CRUD logic
↓
Run Tests & Iterate: pytest, fix failures, re-run until green

The Human in the Loop

Vibe coding is collaborative, not hands-off

AI Does Well

  • Translating requirements to code structure
  • Writing boilerplate and repetitive code
  • Following established patterns
  • Generating test cases from specs
  • Refactoring with consistent style

Human Must Do

  • Define the requirements clearly
  • Review all generated code
  • Make architecture decisions
  • Validate business logic correctness
  • Catch security vulnerabilities
Vibe coding does NOT mean "accept everything the AI writes." You are still the architect, reviewer, and quality gate. The AI is a force multiplier, not a replacement for understanding your code.

A LLMs are too slow to process code
B Code is harder to understand than natural language
C Codebases have millions of tokens but LLM context windows are limited
D Context isn't important for code generation
Why C? Even the largest context windows (200K tokens) can hold only a fraction of a typical codebase. The agent must intelligently select the most relevant files and snippets using strategies like file relevance scoring, AST extraction, and dependency graph traversal. Wrong context leads to wrong code.

Answer: Question 3
What distinguishes CLI agents (like Claude Code) from IDE agents (like Copilot)?
A CLI agents can only read files, IDE agents can edit
B CLI agents have full shell access and can run any command autonomously
C IDE agents are always more accurate than CLI agents
D CLI agents don't support conversation
Why B? CLI agents operate in the terminal with full shell access — they can run tests (pytest), use git (commit, branch, diff), execute linters, install packages, and more. IDE agents are embedded in the editor and primarily work through the IDE's API. Both can read and edit files, but CLI agents have broader tool access.

Answer: Question 4
When is vibe coding LEAST appropriate?
A Prototyping a new feature
B Writing CRUD API endpoints
C Security-critical authentication code
D Learning a new framework
Why C? Security-critical code (authentication, encryption, access control) requires deep human expertise and careful review. AI can introduce subtle vulnerabilities that look correct but are exploitable. Prototyping (A), CRUD (B), and learning (D) are all excellent use cases for vibe coding because mistakes are low-cost and easily caught.

Answer: Question 5
What makes a "great" prompt for an AI coding agent?
A Being as brief as possible
B Including specific file, error, expected behavior, and validation steps
C Writing the solution yourself and asking the AI to review it
D Using technical jargon to impress the AI
Why B? A great prompt follows the Task / Context / Expected Behavior / Validation template. Specific file paths, error messages, expected outcomes, and validation commands give the agent everything it needs to solve the problem in one pass. Brevity (A) often means missing context. Jargon (D) doesn't help — clarity does.
