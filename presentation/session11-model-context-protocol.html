MCP Overview & Architecture

The Problem · Protocol Spec · Client-Server Model · Three Primitives

The Problem MCP Solves

Without MCP

  • Every AI tool builds custom integrations
  • N agents × M tools = N×M integrations
  • Fragmented, non-standard, brittle
  • Each agent speaks a different “language” to tools
  • Switching agents means rewriting all tool bindings

With MCP

  • Standard protocol for all AI-tool communication
  • N agents + M tools = N+M integrations
  • Build a tool once, use with any MCP-compatible agent
  • Build an agent once, connect to any MCP server
  • Like USB-C for AI tools
Before USB, every phone had a different charger. MCP is the USB-C of AI tool integration — one standard protocol that works with any agent.

The Three Primitives

Tools

Model-controlled actions

Functions the LLM can call. Like POST endpoints.

Examples:
• search_code
• run_tests
• query_db
• create_file

Resources

Application-controlled data

Read-only context for the LLM. Like GET endpoints.

Examples:
• file://config.yaml
• db://schema
• git://log
• project://structure

Prompts

User-controlled templates

Pre-built prompt patterns. Like saved queries.

Examples:
• code_review
• explain_code
• generate_tests
• summarize_diff

JSON-RPC 2.0 Protocol

All MCP communication uses JSON-RPC 2.0 request/response messages

// Client → Server (tool call) { "jsonrpc": "2.0", "id": 1, "method": "tools/call", "params": { "name": "search_code", "arguments": {"query": "def authenticate", "path": "src/"} } } // Server → Client (response) { "jsonrpc": "2.0", "id": 1, "result": { "content": [{"type": "text", "text": "Found 3 matches in auth.py..."}] } }

Transport Layers

stdio (Default)

  • Communication via stdin/stdout
  • Best for local tools
  • Agent spawns server as subprocess
  • Used by Claude Code, OpenCode, Cursor
  • Zero network setup required
  • One client per server process

SSE (Server-Sent Events)

  • HTTP-based streaming
  • Best for remote/shared servers
  • Multiple clients can connect
  • Used for team-shared tools
  • Works through firewalls and proxies
  • Supports authentication headers
stdio is like a walkie-talkie — direct, one-to-one communication. SSE is like a radio station — one server broadcasting to many listeners over the network.

Capability Negotiation

The initialize handshake tells each side what the other supports

// Client → Server: initialize request { "jsonrpc": "2.0", "id": 0, "method": "initialize", "params": { "protocolVersion": "2024-11-05", "capabilities": { "roots": {"listChanged": true}, "sampling": {} }, "clientInfo": {"name": "claude-code", "version": "1.0"} } } // Server → Client: initialize response { "jsonrpc": "2.0", "id": 0, "result": { "protocolVersion": "2024-11-05", "capabilities": { "tools": {"listChanged": true}, "resources": {"subscribe": true}, "prompts": {"listChanged": true} }, "serverInfo": {"name": "my-tools", "version": "0.1.0"} } }

MCP Connection Lifecycle

1
Initialize — Client sends capabilities, server responds with its capabilities and available primitives
2
Discover — Client calls tools/list, resources/list, prompts/list to learn what’s available
3
Operate — Client calls tools/call, resources/read, prompts/get as the LLM requests
4
Shutdown — Clean disconnection when the host application closes
The initialize handshake is like a first meeting: “Here’s who I am and what I can do.” Both sides agree on protocol version and capabilities before any real work begins.

Building MCP Servers in Python

SDK · FastMCP · Decorators · Testing

MCP Python SDK

FastMCP makes building MCP servers as easy as building a Flask app

pip install mcp from mcp.server.fastmcp import FastMCP mcp = FastMCP("my-server") @mcp.tool() def search_code(query: str, path: str = ".") -> str: """Search for code patterns in the codebase.""" # Implementation here return f"Found matches for '{query}' in {path}" @mcp.resource("file://{path}") def read_file(path: str) -> str: """Read a file from the project.""" with open(path) as f: return f.read() @mcp.prompt() def code_review(code: str) -> str: """Generate a code review prompt.""" return f"Review this code for bugs, style, and security:\n\n{code}"

Tool Decorators Deep Dive

@mcp.tool() def code_metrics(file_path: str, include_complexity: bool = True) -> str: """Analyze code quality metrics for a Python file. Args: file_path: Path to the Python file to analyze include_complexity: Whether to calculate cyclomatic complexity """ import ast with open(file_path) as f: tree = ast.parse(f.read()) functions = [n for n in ast.walk(tree) if isinstance(n, ast.FunctionDef)] classes = [n for n in ast.walk(tree) if isinstance(n, ast.ClassDef)] return f"Functions: {len(functions)}, Classes: {len(classes)}"
Type hints become the tool’s JSON schema. Docstrings become the description the LLM sees. The LLM uses these to decide when and how to call your tool.

Resources — Exposing Context

Resources provide read-only data that enriches the LLM’s context

@mcp.resource("project://structure") def project_structure() -> str: """Return the project directory tree.""" # Static resource — always available return subprocess.run( ["tree", "-L", "2"], capture_output=True, text=True ).stdout @mcp.resource("config://{name}") def get_config(name: str) -> str: """Read a configuration file by name.""" # Dynamic resource with URI template config_path = f"config/{name}.yaml" with open(config_path) as f: return f.read()

Static Resources

Fixed URI like project://structure. Always returns the same type of data. Listed in resources/list.

Dynamic Resources

URI templates like config://{name}. Parameters extracted from the URI. Infinite possible resources from one handler.

Prompts — Reusable Templates

Pre-built prompt patterns that users can invoke through the MCP client

from mcp.server.fastmcp import FastMCP from mcp.types import TextContent mcp = FastMCP("dev-prompts") @mcp.prompt() def code_review(code: str, language: str = "python") -> str: """Generate a thorough code review prompt.""" return f"""Review this {language} code for: 1. Bugs and logic errors 2. Security vulnerabilities 3. Performance issues 4. Code style and readability Code to review: ```{language} {code} ```""" @mcp.prompt() def generate_tests(code: str, framework: str = "pytest") -> str: """Generate unit tests for the given code.""" return f"""Write {framework} unit tests for this code. Cover edge cases and error handling. Code: ```python {code} ```"""

Running & Testing MCP Servers

# Run the server (stdio transport — default) python my_server.py # Test with MCP Inspector (interactive browser UI) npx @modelcontextprotocol/inspector python my_server.py # Configure in Claude Code (claude_desktop_config.json) { "mcpServers": { "my-tools": { "command": "python", "args": ["my_server.py"] } } } # Configure with SSE transport for remote access { "mcpServers": { "remote-tools": { "url": "http://tools.example.com:8080/sse" } } }
The MCP Inspector is your best friend during development. It shows all tools, resources, and prompts your server exposes, and lets you test them interactively.

Complete Server Example

# my_server.py — A complete MCP server from mcp.server.fastmcp import FastMCP import subprocess, json mcp = FastMCP("dev-assistant") @mcp.tool() def run_tests(test_path: str = "tests/") -> str: """Run pytest and return results.""" result = subprocess.run( ["python", "-m", "pytest", test_path, "-v", "--tb=short"], capture_output=True, text=True, timeout=60 ) return f"Exit code: {result.returncode}\n{result.stdout}\n{result.stderr}" @mcp.resource("project://dependencies") def get_dependencies() -> str: """List project dependencies from requirements.txt.""" with open("requirements.txt") as f: return f.read() @mcp.prompt() def explain_error(error: str) -> str: """Help debug an error message.""" return f"Explain this error and suggest fixes:\n\n{error}" if __name__ == "__main__": mcp.run() # Starts stdio transport by default

Database MCP Server

Example: A simple SQLite query tool exposed via MCP

import sqlite3 from mcp.server.fastmcp import FastMCP mcp = FastMCP("database") DB_PATH = "app.db" @mcp.tool() def query_db(sql: str) -> str: """Execute a read-only SQL query and return results. Args: sql: A SELECT query to execute (writes are blocked) """ if not sql.strip().upper().startswith("SELECT"): return "Error: Only SELECT queries are allowed" conn = sqlite3.connect(DB_PATH) try: cursor = conn.execute(sql) columns = [d[0] for d in cursor.description] rows = cursor.fetchall() return f"Columns: {columns}\nRows: {rows}" finally: conn.close() @mcp.resource("db://schema") def get_schema() -> str: """Return the database schema.""" conn = sqlite3.connect(DB_PATH) cursor = conn.execute("SELECT sql FROM sqlite_master WHERE type='table'") return "\n".join(row[0] for row in cursor.fetchall())

MCP vs LangChain Tools

Feature MCP LangChain Tools
Protocol JSON-RPC 2.0 standard Python function interface
Transport stdio, SSE (network) In-process only
Discovery Client queries server at runtime Hardcoded in agent code
Multi-agent Any MCP client can use LangChain only
Resources First-class primitive No equivalent
Ecosystem Growing (100+ servers) Large (LangChain community)
Best for Tool standardization across agents Quick prototyping within LangChain

Security Considerations

MCP servers can execute code, read files, and access databases. Security is not optional — it’s critical.

Input Validation

  • Always validate tool arguments
  • Sanitize file paths (no ../../etc/passwd)
  • Limit query scope and complexity
  • Whitelist allowed operations

Sandboxing

  • Run servers with minimal permissions
  • Use subprocess isolation
  • Set timeouts on all operations
  • Restrict filesystem access to project dir

Secrets Management

  • Never expose API keys in MCP responses
  • Use environment variables for credentials
  • Audit tool call logs for data leaks
  • Rotate credentials regularly

Bridging MCP and LangChain

Use MCP tools within a LangChain agent — best of both worlds

# Concept: Use MCP tools within a LangChain agent from langchain.tools import StructuredTool def create_langchain_tool_from_mcp(mcp_tool, mcp_client): """Bridge an MCP tool to LangChain.""" return StructuredTool.from_function( func=lambda **kwargs: mcp_client.call_tool(mcp_tool.name, kwargs), name=mcp_tool.name, description=mcp_tool.description, ) # Usage: discover MCP tools and convert to LangChain tools mcp_tools = mcp_client.list_tools() langchain_tools = [ create_langchain_tool_from_mcp(t, mcp_client) for t in mcp_tools ] # Now use in a LangChain agent agent = create_react_agent(llm, langchain_tools)
You don’t have to choose. Use MCP for tool standardization and LangChain for orchestration. Bridge them together for maximum flexibility.

Question 1 of 5

What are the three primitives in MCP?

A Request, Response, Stream
B Tools, Resources, Prompts
C Read, Write, Execute
D Client, Server, Transport
B — Tools, Resources, Prompts. Tools are model-controlled actions, Resources are application-controlled data, and Prompts are user-controlled templates. These three primitives form the foundation of every MCP server.
Question 2 of 5

What protocol does MCP use for communication?

A REST API over HTTP
B GraphQL subscriptions
C JSON-RPC 2.0
D gRPC with protobuf
C — JSON-RPC 2.0. MCP uses JSON-RPC 2.0 as its wire protocol, transported over either stdio (local) or SSE (remote). This provides a simple, well-established request/response format.
Question 3 of 5

How do MCP tool descriptions get generated in the Python SDK?

A Manually written in a config file
B Automatically from Python type hints and docstrings
C The LLM generates them at runtime
D They must be registered in a central registry
B — Automatically from Python type hints and docstrings. FastMCP uses type annotations to generate the JSON schema for tool parameters, and docstrings become the description that the LLM reads to understand when and how to use the tool.
Question 4 of 5

What is the key advantage of MCP over custom tool integrations?

A MCP is faster than direct function calls
B MCP standardizes the protocol so N agents + M tools = N+M integrations instead of N×M
C MCP tools are always more secure
D MCP eliminates the need for API keys
B — N+M instead of N×M. Like USB-C, one standard protocol works with any compatible agent. Build a tool once and every MCP-compatible agent (Claude Code, OpenCode, Cursor, custom agents) can use it without custom integration work.
Question 5 of 5

When would you choose SSE transport over stdio?

A When running tools locally on the same machine
B When you need the fastest possible communication
C When multiple clients need to connect to a shared, remote MCP server
D When the server needs to call back to the client
C — Shared, remote access. SSE (Server-Sent Events) is HTTP-based, enabling multiple clients to connect to a single MCP server over the network. This is ideal for team-shared tools, remote servers, and scenarios where the server runs on a different machine.
