What is LangChain?

LangChain is an open-source Python framework that provides building blocks to create applications powered by LLMs — from simple chatbots to complex multi-agent systems.

70M+

Monthly downloads

Production Ready

Stable 1.0 release

90K+ GitHub Stars

Largest LLM framework

If LLMs are engines, LangChain is the car chassis. It gives you a steering wheel (prompts), gearbox (chains), dashboard (memory), and toolkit (tools) — so you can build a complete vehicle instead of just having a powerful engine sitting on the floor.

Core Design Philosophy

Composable

Small pieces that snap together like LEGO blocks. Mix and match models, prompts, tools, and memory.

Model-Agnostic

Switch from Ollama to Groq to OpenAI by changing one line. Your agent logic stays the same.

Declarative

Describe what you want (prompt | model | parser), not how to execute it step by step.

Observable

Built-in tracing and callbacks. See every step your agent takes. Essential for debugging and production.

Working with Models & Prompts

LLM Integration · Prompt Templates · Message Types

Connecting to an LLM

Two lines of code to talk to an AI

# Using Ollama (local, free) - Day 1
from langchain_ollama import ChatOllama

llm = ChatOllama(model="llama3.2:1b")
response = llm.invoke("What is Python?")
print(response.content)
# Using Groq (cloud, free) - Day 2 onwards
from langchain_groq import ChatGroq

llm = ChatGroq(model="llama-3.3-70b-versatile")
response = llm.invoke("What is Python?")
print(response.content)
Notice: the .invoke() call is identical. Only the import and model name change. This is LangChain's model-agnostic design — swap providers without rewriting your app.

Message Types

LLMs communicate through structured messages

SystemMessage

Sets the agent's behavior and personality

"You are a helpful travel assistant who speaks Hindi and English."

HumanMessage

The user's input / question

"Find me flights to Tokyo."

AIMessage

The LLM's response

"I found 3 flights. The cheapest is..."

ToolMessage

Result from a tool call, fed back to the LLM

{"flights": [{"airline": "AI", "price": 38500}]}

Messages in Code

from langchain_core.messages import SystemMessage, HumanMessage
from langchain_ollama import ChatOllama

llm = ChatOllama(model="llama3.2:1b")

messages = [
    SystemMessage(content="You are a helpful assistant. Be concise."),
    HumanMessage(content="What are the 3 largest oceans?")
]

response = llm.invoke(messages)
print(response.content)

# Pacific Ocean, Atlantic Ocean, Indian Ocean
The SystemMessage is like a job description you give to a new employee before they start working. It shapes how the LLM responds to every question that follows.

Prompt Templates

Reusable prompts with variables

Hard-coded (bad)

llm.invoke("Translate 'hello'
to French")

Can't reuse. Need a new string for every language.

Template (good)

"Translate '{text}'
to {language}"

Reusable! Pass any text and language.

Templates let you define the structure once and fill in the variables at runtime. This makes your prompts consistent, testable, and easy to improve over time.

ChatPromptTemplate

from langchain_core.prompts import ChatPromptTemplate

# Define the template with variables in {curly braces}
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a translator. Translate accurately."),
    ("human", "Translate '{text}' to {language}")
])

# Fill in the variables
messages = prompt.invoke({
    "text": "Good morning",
    "language": "Japanese"
})

# Send to LLM
response = llm.invoke(messages)
print(response.content)
# おはようございます (Ohayou gozaimasu)
04

Chains & LCEL

The Pipe Syntax · Chain Composition · Output Parsing

What is a Chain?

Connect components into a workflow

📝 Prompt
Prepare the input
|
🧠 Model
Process with LLM
|
📤 Parser
Format the output
chain = prompt | llm | output_parser
A chain is like an assembly line in a factory. Raw materials (user input) enter one end, pass through stations (prompt, model, parser), and a finished product (structured output) comes out the other end. Each station does one job and passes its result to the next.

LCEL: LangChain Expression Language

The pipe | operator

LCEL lets you compose chains using the pipe operator |
Just like Unix pipes: cat file.txt | grep "error" | wc -l

The output of each step automatically becomes the input of the next.

Without LCEL (verbose)

msgs = prompt.invoke(input)
resp = llm.invoke(msgs)
out = parser.invoke(resp)

With LCEL (clean)

chain = prompt | llm | parser
out = chain.invoke(input)

Same result. LCEL is shorter, more readable, and gives you streaming + async for free.

Your First Chain

from langchain_ollama import ChatOllama
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 1. Prompt template
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant. Be concise."),
    ("human", "{question}")
])

# 2. LLM
llm = ChatOllama(model="llama3.2:1b")

# 3. Output parser (extracts just the text)
parser = StrOutputParser()

# 4. Chain them with LCEL pipe syntax
chain = prompt | llm | parser

# 5. Run it!
result = chain.invoke({"question": "What is Docker?"})
print(result)
# "Docker is a platform for containerizing applications..."

What Happens Inside the Chain?

Data flows through each step automatically

Step Component Input Output
1 Prompt Template {"question": "What is Docker?"} List of formatted messages
2 LLM (ChatOllama) List of messages AIMessage object (with .content, .metadata)
3 StrOutputParser AIMessage object Plain string: "Docker is a platform..."
Each component transforms its input and passes the result to the next. The parser at the end extracts just the text you need — no need to manually access .content on the response object.

Output Parsers

Get structured data from LLM responses

StrOutputParser

Extracts plain text from the response

"Docker is..."

JsonOutputParser

Parses JSON from the response

{"name": "Docker"}

PydanticOutputParser

Validates into a Python class

Tool(name="Docker")
LLMs return free-form text. Parsers are like customs officers who check the output and convert it into the exact format your application expects — a string, a JSON object, or a validated Python object.

Pydantic Output Parser

Get validated, typed Python objects from LLM output

from langchain_core.output_parsers import PydanticOutputParser
from pydantic import BaseModel, Field

class MovieReview(BaseModel):
    title: str = Field(description="Movie title")
    rating: int = Field(description="Rating 1-10")
    summary: str = Field(description="One line summary")

parser = PydanticOutputParser(pydantic_object=MovieReview)
prompt = ChatPromptTemplate.from_messages([
    ("system", "Review movies. {format_instructions}"),
    ("human", "Review: {movie}")
])

chain = prompt | llm | parser
review = chain.invoke({"movie": "Inception",
    "format_instructions": parser.get_format_instructions()})

# review.title = "Inception" | review.rating = 9 | review.summary = "A mind-bending..."

Chaining Multiple Steps

Chains can feed into other chains

# Chain 1: Generate a topic
topic_prompt = ChatPromptTemplate.from_template(
    "Give me one interesting topic about {subject}"
)
topic_chain = topic_prompt | llm | StrOutputParser()

# Chain 2: Write about the topic
write_prompt = ChatPromptTemplate.from_template(
    "Write a 3-sentence explanation of: {topic}"
)
write_chain = write_prompt | llm | StrOutputParser()

# Combined: topic output feeds into write input
full_chain = topic_chain | (lambda topic: {"topic": topic}) | write_chain
This is the "chaining" we talked about in Session 1 — now you see it in real code. Small, focused chains composed into larger workflows. This is how production agents are built.

Three Ways to Run a Chain

.invoke()

Run once, get complete result

result = chain.invoke(
  {"q": "hi"})
# waits for full response

Best for: scripts, APIs

.stream()

Get tokens as they're generated

for chunk in chain.stream(
  {"q": "hi"}):
  print(chunk, end="")

Best for: chat UIs

.batch()

Process multiple inputs at once

results = chain.batch([
  {"q": "hi"},
  {"q": "bye"}
])

Best for: bulk processing

All three methods work on any LCEL chain automatically. No extra code needed.

What does StrOutputParser do in a chain?
A Converts the prompt into a string
B Extracts just the text content from the LLM's AIMessage response
C Validates that the output is valid JSON
D Translates the output to English
Why B? The LLM returns an AIMessage object with metadata, not just text. StrOutputParser extracts the .content string so you get clean text instead of dealing with the full message object. For JSON, you'd use JsonOutputParser.

Answer: Question 5
Which of these is a valid LCEL chain?
A chain = llm + prompt + parser
B chain = prompt | llm | parser
C chain = parser | prompt | llm
D chain = prompt.run(llm, parser)
Why B? LCEL uses the pipe | operator, and the order matters: prompt first (prepares the input), then LLM (processes it), then parser (formats the output). Option C has the order backwards. Option A uses + which isn't LCEL syntax.
