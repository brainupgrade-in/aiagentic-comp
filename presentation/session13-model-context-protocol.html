01

MCP Architecture

The Problem · Protocol Spec · Three Primitives · Protocol Essentials

The Problem MCP Solves

Without MCP

  • Every AI tool builds custom integrations
  • N agents × M tools = N×M integrations
  • Fragmented, non-standard, brittle
  • Each agent speaks a different “language” to tools
  • Switching agents means rewriting all tool bindings

With MCP

  • Standard protocol for all AI-tool communication
  • N agents + M tools = N+M integrations
  • Build a tool once, use with any MCP-compatible agent
  • Build an agent once, connect to any MCP server
  • Like USB-C for AI tools
Before USB, every phone had a different charger. MCP is the USB-C of AI tool integration — one standard protocol that works with any agent.

The Three Primitives

Tools

Model-controlled actions

Functions the LLM can call. Like POST endpoints.

Examples:
• query_database
• search_code
• create_ticket
• send_message

Resources

Application-controlled data

Read-only context for the LLM. Like GET endpoints.

Examples:
• db://schema
• confluence://page/123
• git://log
• metrics://dashboard

Prompts

User-controlled templates

Pre-built prompt patterns. Like saved queries.

Examples:
• analyze_incident
• summarize_sprint
• review_pr
• explain_metric

Protocol Essentials

JSON-RPC 2.0 · Transport · Connection Lifecycle

JSON-RPC 2.0

  • All messages: {"jsonrpc":"2.0", ...}
  • Methods: tools/list, tools/call, resources/read, prompts/get
  • Request has id + method + params
  • Response has id + result

Transport

  • stdio — local, agent spawns server as subprocess (Claude Code, Cursor)
  • SSE — HTTP-based, remote/shared servers, multiple clients
  • Transport is pluggable; protocol stays the same

Lifecycle

  • Initialize — exchange capabilities
  • Discover — list tools, resources, prompts
  • Operate — call tools, read resources
  • Shutdown — clean disconnect
MCP is a protocol, not a library. Any language, any agent, any tool — if they speak JSON-RPC 2.0 over stdio or SSE, they work together.

Enterprise MCP Use Cases

Fortune 500 Adoption · Data Access · Developer Productivity · ROI

Why Fortune 500 Companies Adopt MCP

In the 2000s, enterprises adopted ESBs (Enterprise Service Buses) to standardize application integration. MCP is the ESB for the AI era — one protocol connecting all AI agents to all enterprise tools and data.

The Enterprise Problem

  • Dozens of internal tools: Jira, Confluence, Salesforce, Snowflake, GitHub, Slack...
  • Each AI vendor builds custom connectors
  • N AI products × M enterprise tools = integration chaos
  • Security review needed for every point-to-point connection

The MCP Solution

  • Each tool exposes one MCP server
  • Any AI agent connects via the standard protocol
  • Centralized security and audit layer
  • Swap AI vendors without re-building integrations
  • New tools available to all agents instantly

Configuring MCP Clients

Most AI agents use a JSON config file to connect to MCP servers

Claude Desktop Config

{ "mcpServers": { "postgres": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"] } } }

Claude Code Config

{ "mcpServers": { "github": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"], "env": { "GITHUB_TOKEN": "ghp_..." } } } }
Pattern: command + args = stdio transport (local). url = SSE transport (remote). env passes secrets without hardcoding.

Multi-Server Configuration

Connect one agent to five MCP servers — each with its own scope and credentials

{ "mcpServers": { "postgres": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-postgres", "$DB_URL"] }, "github": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"], "env": {"GITHUB_TOKEN": "$GH_TOKEN"} }, "slack": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-slack"], "env": {"SLACK_BOT_TOKEN": "$SLACK_TOKEN"} }, "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/projects"] }, "confluence": { "url": "https://mcp-gateway.internal/confluence/sse" } } }

Bridging MCP with LangChain

Use langchain-mcp-adapters to bring MCP tools into LangChain agents

# pip install langchain-mcp-adapters from langchain_mcp_adapters.client import MultiServerMCPClient from langgraph.prebuilt import create_react_agent # Connect to MCP servers async with MultiServerMCPClient({ "math": {"command": "python", "args": ["math_server.py"]}, "weather": {"url": "http://localhost:8080/sse"}, }) as client: tools = client.get_tools() # Auto-converts MCP tools to LangChain tools agent = create_react_agent(llm, tools) result = await agent.ainvoke({ "messages": [("user", "What's 2+2 and weather in SF?")] })
MCP for tool standardization + LangChain/LangGraph for orchestration. The adapter bridges both worlds — MCP servers become LangChain tools automatically.

Enterprise Security & Governance

MCP servers can execute code, query databases, and call external APIs. Enterprise deployment demands defense in depth.

Input Validation

  • Sanitize all tool arguments
  • Block path traversal (../../)
  • Enforce read-only for data queries
  • Limit payload sizes

Access Control

  • Role-based MCP server assignment
  • Analysts: data servers only
  • Developers: code + CI/CD servers
  • Admins: full server access

Audit & Monitoring

  • Log every tool call + arguments
  • Track who accessed what data
  • Alert on anomalous patterns
  • Compliance reporting (SOC2, GDPR)

MCP vs REST APIs vs LangChain Tools

Feature MCP REST APIs LangChain Tools
Designed For AI agent ↔ tool communication App ↔ app communication LangChain agent orchestration
Discovery Runtime (tools/list) Static (OpenAPI docs) Hardcoded in agent code
Transport stdio or SSE HTTP In-process (Python)
Schema JSON-RPC + auto from types OpenAPI / Swagger Pydantic models
Multi-Agent Any MCP client can connect Any HTTP client can call LangChain only
Best For Standardized AI tool access Service-to-service APIs Rapid prototyping in Python
Use MCP when you need agent-agnostic tool access. Use REST APIs for service-to-service. Use LangChain tools for quick Python prototypes. They are complementary.
